# External ideas used, with attribution

The eligibility page allows re-using an existing implementation only “if the original authors grant you the rights to use their solution and if you made significant modifications”, and says that re-using code with a rewritten input and output is not sufficient. We therefore did not take code from other teams. Where we took an idea from public text (a README, a research note, a journal article, a post in the OpenSky Discord channel #prc-data-competition) it is listed here with its source, the license of the source where one exists, what exactly we took, and where our own implementation is. Licenses were read from the GitHub repository metadata on 2026-10-08.

## 3. Originality audit of this repository

Method (read-only, by script: `research/audit/foreign_audit.py` and `research/audit/foreign_lines.py`, run on 2026-10-08. They read our saved copies of other teams' code, which this repository does not redistribute; their full outputs quote that code and are left out too; the counts below are in `research/audit/foreign_audit_summary.json`):

1. Corpus of foreign code: every saved Python file of other teams that we had in the working tree (5 files: three analysis scripts of versatile-violin, one script of a participant repository, one prior-computation script of another team), plus every fenced code block of the 15 saved Markdown documents of other teams.
2. Our corpus: all 785 Python files under `src/`, `tools/` and `research/` of the working tree.
3. Tests: (a) function bodies with at least 5 statements, hashed as AST dumps (exact and with all variable and function names replaced); (b) containment of 10-token shingles (names, strings and numbers abstracted) of each foreign file in each of our files; (c) identical source lines of at least 38 characters (whitespace normalised, comments, imports and prints excluded); (d) shared identifiers and string literals.
4. Result: no function body of ours equals a foreign function body, exactly or after renaming. The 10-token containment values are at most 0.19 and are dominated by common pandas and NumPy idioms (the highest, 0.19, is for the evaluation code of the PRU rule mentioned in section 2, which is not shipped). Identical lines exist only in that evaluation code (11 lines in `research/r10_a/pru_cal.py`, 6 in `tools/prucal.py` and `tools/prucal2.py`, 1 in `research/r10_a/prucal_495_check.py`). None of these files is part of this repository and no manifest of any submitted file (v1 to v35) lists them.
5. Limits: the audit compares against the foreign code we saved; code of other teams that we never opened cannot be compared. The saved copies of the repository `arnavhm/prc_26` were taken on 2026-10-07.
